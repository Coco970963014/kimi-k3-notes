### 7.3 内存优化特性二：swap activation（activation offload）

确定接入，与重计算并列作为内存轨道的单变量候选（第一轮不与 FullAC 叠加做 A/B）。

**方案调研结论**：TorchTitan 无原生 swap activation 实现。FSDPTurbo 的交换机制（`TensorSwapContext`：saved-tensor pack/unpack 钩子 + pinned host buffer + 独立异步 D2H/H2D 流 + 按层索引 prefetch + `storage().resize_(0)` 释放设备显存）经源码核对，**机制本身覆盖模块内所有为 backward 保存的 tensor，包括内部中间量**；"只换模块输入"来自其默认 check_fn 的策略选择，不是机制限制。照搬默认策略对 K3 收益确实低（单层输入约 8 MiB × 13 层，而约 20 GiB 主体在 KDA/MLA/MoE 内部中间量），因此正确路线是**复用其基础设施、重写选择策略**。

**K3 专用设计要点**：

1. 选择策略从"同输入 storage"改为大小阈值（如 ≥64 MiB 才换出），避免小 tensor 碎拷贝；
2. **跨层存活 tensor 必须排除**：K3 Attention Residual 的 `block_residual_TND` 由前层产生、被同窗口后层 forward 直接使用，被换出并释放 storage 会破坏后续层计算——需在 check_fn 排除或按 attn-res 窗口分组延迟释放，这是 K3 区别于标准 decoder 的关键边界；
3. FSDP2 交互：参数已排除（Parameter 检查），通信输出 tensor 的换出与 reshard 行为需专项验证。

**前置验证与执行顺序**（均需用户确认后启动）：

1. 组件门（零 NPU 训练成本）：`torch.accelerator.Stream/Event`、`pin_memory=True`、`storage().resize_(0)` 在 torch_npu 2.12 + CANN 9.1.0 的行为实测；
2. 证据先行：用已归档 memory trace 的 `operator_memory.csv`/`npu_module_mem.csv` 分解 20 GiB 激活构成，估算可交换集合与阈值（只读分析）；
3. 快速基线：先用 PyTorch 原生 `torch.autograd.graph.save_on_cpu(pin_memory=True)`（全量换出、同步无 prefetch）验证正确性并测得内存收益上限；
4. 正式实现：借鉴 FSDPTurbo 基础设施实现异步/prefetch 版本，独立 worktree 走 CPU 梯度门 → 单卡/四卡 smoke → 压力 workload 内存 run → 成对 60-step A/B（内存与吞吐双报告）。

**预期收益**：机制上稳态设备侧激活可降至约"单层在飞量"；KDA backward 占设备算子时间 82% 佐证中间量主体在 KDA 路径，收益量级应显著大于 `num_chunks=16` 的 2 GiB。host 侧约 1.6 TiB 内存容量不构成约束；主要代价是 backward 期 H2D 传输延迟，依赖 prefetch 与计算重叠（当前 Computing 91.3%、Free 6.8% 是可利用的重叠空间）。
