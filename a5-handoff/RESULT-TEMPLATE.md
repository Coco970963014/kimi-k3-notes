# A5 执行结果模板

本模板供教师 agent 根据用户口述整理记录，不要求用户填写或传回文件。实际记录另存为 `results/<task-id>-<run-id>.md`，不要覆盖本模板；原始日志保留在内网。未口述的信息填 UNKNOWN，不推定通过。

## 用户最少反馈

简单操作只需说“做了什么、看到什么、有没有报错”。复杂运行由教师指定本轮必需的少量指标；错误先说失败步骤和错误关键词，再按需要在内网查看局部信息。不要求口述完整日志。

## 身份

- 任务 ID：
- 指令版本：用户转交的文档 commit SHA；未知写 UNKNOWN，不填写模型代码 SHA
- Run ID：本次唯一标识，重试必须换新 ID
- 机器别名：
- 执行时间与时区：
- 执行位置：宿主机 / 容器；venv/Conda 状态
- 实际执行范围：
- 执行者：用户手动 / 内网 agent / UNKNOWN
- 证据来源：用户口述，外网教师未核对原始日志

## 结论

- 执行结果：PASS / FAIL / BLOCKED（三选一；未执行用 BLOCKED）
- 结论范围：仅当前任务，不代表后续门禁通过
- 各命令退出码：逐条填写；未执行写 NOT_RUN
- 本地完整日志/产物路径：脱敏路径；没有文件则明确说明仅有终端输出

## 输出摘要

记录用户口述的关键版本、状态和数值。确有转述的脚本 JSON 或 SUMMARY.txt 才记录，不要求传回。摘要缺少关键版本/健康状态时，教师提出定向追问；不要以脚本整体退出码代替分项检查。

## 补充事实

- 当前任务要求的人工补充项：逐项回答，未知写 UNKNOWN
- 版本组验证依据：版本/构建批次及是否有内部确认，不含内部 URL
- TorchTitan SHA 与工作区状态：本轮未要求或未获取时写 NOT_COLLECTED
- 是否修改环境或代码：无 / 具体变更及授权依据

## 首个错误

用户明确确认无错误才写 NONE；否则记录口述的失败步骤、首个错误类型和关键词，未确认写 UNKNOWN。必要时指导用户在内网查看首个错误附近日志，只口述定位所需的函数、算子、shape 或错误码，不要求传回 30 行日志。不得仅凭最后一条汇总异常确定根因。

- 教师验收：PENDING / 基于用户口述放行 / 不通过；说明证据缺口，不将口述放行表述为已独立核验原始日志
