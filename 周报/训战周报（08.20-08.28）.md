## 四、本周工作与成果

### 1. 完成 E2 新基线迁移（主线合入版，1.02B 参数）

- 上游 PR #4025 于 08-24 合入主线（`5fecad92`），debugmodel 放大至 1.02B 参数（E0/E1 的 10.2 倍）；FlexAttention 被当前 Triton-Ascend 编译链阻断，以兼容补丁（11 文件，+242/-24）回退为 SDPA 路径，四卡 60-step 训练健康（CV 0.23%）。
- 基线 workload 定为 8192 tokens/rank：E1 同级 workload（16384）无重计算时首个 forward 即 OOM，容量上限由模型规模决定。
- 三线对比确认演进趋势：E0→E1（SDPA 替换手写 eager MLA）吞吐 +6.2%、forward active -61%；E2 每 token 耗时为 E1 的 9.3 倍，优于按参数量（10.2x）线性劣化约 10%；optimizer state 按参数等比，非内存优化对象。

### 2. 完成 E2 重计算与 FLA 融合算子单变量特性矩阵

统一口径（四卡、8192 tokens/rank、无 profiler）下完成四组特性实验：

| 特性 | step 时长 | forward active | 结论 |
|---|---:|---:|---|
| FLA 三算子（conv/norm/attnres 融合） | +23.8% | -24.1% | 内存换时延，不在 Pareto 前沿 |
| SelectiveAC（titan 主线默认） | +7.7% | -91.4% | NPU 上非最优 |
| FullAC | **+5.2%** | **-93.8%** | **双维度最优** |
| MemoryBudgetAC | 不可测 | — | 上游 K3 拒绝 compile，阻断 |

核心结论：**FullAC（全量重计算）是当前 NPU 上的最优激活内存方案**——上游默认 SelectiveAC 的 save-op 集合按 CUDA 算子族维护，NPU 算子分发下大量不命中、退化为"近似全重算 + 逐算子策略开销"，建议在 NPU 上直接用 FullAC 替代上游默认。FLA 融合算子方案，在 E1（1 亿）与 E2（10.2 亿）两个规模上复确认为"以过高时延代价换取少量内存收益"，需进一步定位原因。

### 3. 完成 swap activation 验证与理论上限分析，内存路线收口

- P0（`save_on_cpu` 全量搬运）与 P1（选择性 hooks + pinned buffer）两版 swap activation 均打通；显存收益与 FullAC 打平（约 -94%），但时延 +27.6% 远超 FullAC（+4.8%）。
- 带宽实测：pageable D2H 仅 3.0 GB/s（驱动中转 + CPU memcpy 锁死低速段），pinned 达 20.8 GB/s——NPU 搬运必须 pinned。
- 理论上限分析：当前workload，forward耗时占比远低于backward。forward仅占 step 的 5%（0.95s / 18.9s，backward 占 94%）。swap 和 FullAC 消除的其实是同一批激活，即forward产生，即将在backward使用的中间激活。这部分重算的时间代价约为一次前向（0.95秒），而即使将搬运时间做完美异步掩盖，也会有约`1s`的首段Backward无法掩盖，加上H2D与D2H引擎启动代价，**在当前场景下，swap activation最多追平FullAC，无法超过**。可保留为条件性候选（forward 占比 >30% 的 workload、或主机互连升级时再评估）。
- backward 之所以占到 step 的 94%，耗时集中在 KDA 的两个反传内核上——`chunk_kda_bwd_kernel_wy_dA_finalize_npu` 和 `chunk_kda_bwd_kernel_intra_npu`（Python 侧由 `ChunkKDAFunctionBackward` 统一下发）。可进一步探索是否有优化空间。
- 基于以上分析，**决策：暂不投入swap activation异步预取的开发，FullAC 确定为 NPU 基线配置**；swap 保留为条件性候选（forward 占比超过 30% 的 workload 或主机互连升级时再评估）。

## 五、工具使用情况

1. **内存分析（好评）**：MindStudio Insight 内存分析中 Timeline 旗帜标记 + 框选范围联动 Memory 曲线的功能，用于分析不同训练阶段的内存变化（forward/backward/optimizer 各阶段峰值），很好用，建议推广。
2. **改进建议**：① Memory 视图建议增加"从内存曲线跳转至 Timeline"的功能，当前因时间戳偏移量无法对齐，可考虑以选中点距离最近的分配/释放算子作为跳转对齐依据；② Memory 视图建议恢复"回退至最后一次缩放区域"功能（疑似历史功能被误删）。
