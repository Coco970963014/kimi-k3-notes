## 四、本阶段工作与成果

### 1. 完成 FSDP2 兼容性修复，固化正确性基线代码

在 CANN 9.1.0、PyTorch 2.12 + torch_npu 2.12 环境（4 卡 FSDP2 纯数据并行）下，基线 E0（社区 `PR #4025`，commit `9f60a3d6`）在正式训练路径的 chunked loss 两阶段 backward 下，因 `final norm` 与 `lm_head` 共享 FSDP unit 触发未分配 storage 错误。将两者拆为独立 FSDP units 后问题修复，四卡 BF16 训练正确性通过，修复已固化为独立分支 topic/fsdp-compat。该问题也可通过升级 PyTorch nightly 解决，但 torch_npu 版本配套可能滞后，故采用独立 patch 方案。

### 2. 打通 TorchTitan 的 NPU profiler 工具链

TorchTitan 当前不原生支持 `torch_npu.profiler` 采集，完成接入层适配 patch 并通过单卡、四卡功能验证，四 rank CANN trace 产物完整，支撑了后续耗时热点分析与内存归因实验。

### 3. 建立可复现的内存压力与吞吐基线

完成不同 batch/sequence 组合的内存压力搜索，在保持明显内存压力的同时保留足够安全余量。同时完成60-step 无 profiler 长稳测试复核。最终固定 `local_batch_size=2, seq_len=8192` 作为标准压力 workload

### 4. 完成 profile 热点与内存来源归因

- **性能瓶颈**：Computing 占 Stage 91.3%，非重叠通信仅 1.9%，瓶颈是计算而非 HCCL 通信；**KDA backward 两个 kernel 合计占设备算子时间约 82%**，是性能优化的首选对象。
- 内存瓶颈：主要内存负载来自 forward 到 backward 之间长期存活的 activation（after_forward active 约 20.2 GiB），optimizer state 不是主要峰值来源（after_optimizer active 约 194 MiB），allocator peak active/reserved 比例 83%-89%，也排除了空闲缓存或碎片问题。

### 5. 完成 chunked loss 特性对比实验

针对控制 160K 词表 logits 峰值的 TorchTitan 原生 chunked loss，在标准压力 workload 下完成 `num_chunks=4/8/16` 三档单变量对比（profiler memory trace + 60-step 无 profiler 长稳复核）。结论：调大 `num_chunks` 只压缩 lm_head/loss backward 的临时峰值（收益上限约 2 GiB），不降低约 20 GiB 的主激活；`num_chunks=4` 内存表现明显较差，应排除；建议以 `num_chunks=8` 为基准配置，`16` 保留为内存优先场景的候选。

注：源码对比确认：TorchTitan 原生 chunked loss 与 FSDPTurbo `chunk_loss` 数学与内存策略等价，且前者是功能超集，确定不移植、保持"调 TorchTitan 原生参数"路线。

## 五、工具使用情况

本阶段进入正式 profile 采集与调优阶段，记录到两个工具侧问题：

1. TorchTitan 不原生支持 `torch.profiler`/`torch_npu.profiler` 采集，需要接入层适配。已完成适配 patch（topic/torch-npu-profiler 分支）并通过单卡、四卡验证，可作为 NPU 上采集 TorchTitan 训练 trace 的参考做法。
2. 启用 `with_stack=True` 采集时，四个 rank 均会在 profiler native `stop_trace()` 阶段触发 `SIGSEGV`。已确认当前 PyTorch、TorchNPU、CANN 和 Python 版本与官方兼容矩阵一致，具体原因待向 profiler 组件反馈确认。

## 六、下一步计划

1. 迁移新基线：PR #4025 上游已演进 fla-eager 路线（MLA 改用 SDPA/FlexAttention 后端、KDA 短卷积等更换为 fla 融合算子，数值验证脚本已支持 NPU）。计划以 `1da44c1` 之上的 fla 算子最小接入建立新实验基线，rebase FSDP compat 与 profiler patch，过数值正确性门禁后重建 60-step 基线与阶段内存打点。注意 fla 融合算子与 SDPA 会改变 activation 构成，旧 E0 数据保留为内存来源与优化方向的对照依据，绝对数值需在新实现上重新校准。
2. 内存优化特性一（重计算）：K3 的 `parallelize.py` 当前显式不支持 AC，计划仿照 Qwen/Llama 路径增加"FSDP wrap 前应用 AC"的接入，第一轮只做 FullAC 单变量。FSDPTurbo 的 recompute 无可借鉴增量，确定采用 TorchTitan 原生方案；SelectiveAC 的默认 save-ops 集合面向 CUDA 算子，NPU 上需自定义算子集合，排在 FullAC 之后。
3. 内存优化特性二（swap activation）：TorchTitan 无原生实现；FSDPTurbo 的交换机制可覆盖模块内全部 backward 保存 tensor，但默认策略只交换模块输入，对 K3 收益较低（单层输入约 8 MiB × 13 层，而约 20 GiB 主体在 KDA/MLA/MoE 内部中间量）。路线：先用 PyTorch 原生 `save_on_cpu(pin_memory=True)` 做正确性与内存收益上限的 cheap 验证，再复用 FSDPTurbo 基础设施、重写选择策略。
4. 并行特性扩展：HSDP 与 EP 优先。社区 QIU023 分支已提供 TP/EP/PP/CP 四个并行分支作设计参考（CUDA 环境完成 18 种组合数值验证），但其基于自有模型实现与 torch 2.14 nightly + CUDA 生态，与当前 NPU 栈存在版本差距，全部结论需在 NPU 上重新验证，仅作设计参考。HSDP 框架原生支持、以验证为主；EP 为项目既定方向且 K3 的 grouped GEMM 已在 NPU 验证可用；TP/PP/CP 依赖跨 stage adapter 等设计、改动量大，暂缓。
